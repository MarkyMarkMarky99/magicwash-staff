## The rule that drove the cleanup

The user's rule: **documentation lives in `docs/`, never inside source.** This is not a style
preference. A comment passes no gate, so it drifts the moment the code beside it changes, and a
delegated agent then reads that stale prose as ground truth and implements against it. The
contradiction never surfaces as an error — it surfaces as wrong work that passes review. The user
named this a primary Opus failure mode.

So: write no JSDoc blocks, no file headers, no explanatory prose in source. A single short `//`
recording a constraint the code cannot express is the only exception. And when briefing any agent,
state it twice — *write none*, and *do not trust the ones already there; verify against the code.*

Measured proof it matters, from this session: a store documented as impossible to read without
clearing returns the field publicly; a cache documented as consulted once per URL is consulted on
every miss; a card calling itself one of three writers had five callers in four files; two comments
pointed at a module path that does not exist.

## How this session worked, and what to repeat

- **Claude does not read source to do the work; it briefs an agent and verifies the result.** codex
  for audits and large mechanical edits, a general sonnet agent for scoped deletions, grok-explorer
  for scoped research.
- **Never trust an agent's self-report.** Every single delegated result in this session was
  re-verified independently — diff shape, gates run again, cited `file:line` opened. Two audit rows
  turned out to be wrong that way, one of which would have deleted a genuinely useful comment.
- **The instruction that saved that comment:** "if a comment does not match the description, do not
  delete it — report the mismatch instead." Put it in every deletion brief.
- **One codex job at a time on Windows.** Two concurrent runs crash with `0xc0000142`. When the
  harness reports a codex task `killed`, check whether the process survived — it usually has, but
  crippled, spinning on failed `CreateProcess` calls. Kill the tree, clear it, and redispatch rather
  than waiting.
- **Cap explorer fan-out at 3 on this machine.** Nine crashed the run.
- **Verify a test failure against a clean tree** (`git stash`) before assuming your change caused it.
  Six web dry tests fail on an untouched tree; they are listed in MEMORY.md.
