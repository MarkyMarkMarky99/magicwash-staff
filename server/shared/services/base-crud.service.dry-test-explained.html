DRY TEST

ไฟล์นี้ทดสอบอะไร? (อัปเดต 31 เทสต์)

เป็น "Dry Test" ที่ใช้ FakeRepository + Zod schema เพื่อล็อกสัญญา (contract) ของ BaseCrudService ทุกเทสต์ต้องผ่านก่อนและหลังการเปลี่ยนแปลง implementation

การป้องกันก่อนเรียก Repository
  • ตรวจสอบ ID ว่าง/ช่องว่าง → 400
  • ตรวจสอบ Validation → 422
  • ตรวจสอบข้อมูลซ้ำ/ไม่พบ → 404, 409
  • Trim ID ก่อนเรียก repo (getById + update)
Field Projection + Purity
  • คืนเฉพาะ field ตาม response schema
  • ไม่ runtime validate ค่า (ส่ง number เป็นชื่อก็ได้)
  • Explicit non-mutation ของ row จาก repo
  • Project แต่ละ row แยกกันถูกต้อง
พฤติกรรมสำคัญอื่น ๆ
  • list ไม่ slice ผลลัพธ์ (repo จัดการ)
  • Create: omit field ที่ไม่ได้ส่ง, preserve null ถ้าส่งมา
  • Update: strip unknown fields ก่อนส่ง repo
  • Pagination มาจาก validated query เท่านั้น
รหัสข้อผิดพลาดที่ใช้
400 BAD_REQUEST — ID ว่างหรือไม่ถูกต้อง
404 NOT_FOUND — ไม่พบข้อมูล
409 CONFLICT — พบข้อมูลซ้ำ
422 VALIDATION_ERROR — ข้อมูลไม่ผ่าน schema
