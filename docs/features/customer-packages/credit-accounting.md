# Monthly package credit accounting

Staff record package usage by selecting an order on the package detail page. The server reads each order item, resolves its Items item code, and finds an active CREDIT PriceList row for the order's service type and today's effective date. Items without an item ID or matching rate have no computed credits. The preview shows quantity, credit rate, line credits, total, and the current package balance. Confirmation recalculates the same data on the server and appends one negative USAGE referencing the order. The server checks package ownership and eligible service, refuses a second USAGE for the same package and order, and permits a negative balance. The generic transaction endpoint does not accept manual USAGE or TRANSFER. Staff correct a usage with a signed ADJUSTMENT referencing the original PackageTransactions row.

When any preview item has no CREDIT rate, staff can enter a positive decimal credit total for the whole order. The server permits this manual fallback only after recalculating an unrated item, then writes one USAGE with reference source ORDER and notes "manual credits". Fully rated orders retain the computed total and reference source Orders. Either kind of USAGE blocks another usage on the same package and order.

The package detail page can open a CYCLE invoice draft for its own start and expiry dates. The draft contains the package fee, one overage line if the balance is negative, and uninvoiced cash items from orders received in that period. The fee and overage lines can be removed before saving. The overage price is the negative credit balance multiplied by the shared rate of 25 THB per credit. The package credit balance is a usage counter and never a baht balance. A saved overage line carries a package marker in InvoiceItems.sku. After the invoice is saved, staff can record an ADJUSTMENT referencing its invoice number. The server refuses a second overage adjustment for the package and refuses to close overage when the saved line differs from the current negative balance times the credit rate. If the adjustment fails after the invoice saves, the invoice result offers a retry action; staff must check the saved invoice before any new billing attempt.

Renewal is a staff action. The create page uses the old package code, starts the new package the day after the old expiry, and sets the new expiry to one calendar month after the start minus one day. The existing purchase flow creates the invoice and package. If the old balance is positive, staff transfer that amount with one shared reference on both package ledgers. A zero or negative balance is not transferred. The old package detail lists a transfer with either side missing, with an action to write the missing side. The purchase flow may leave an opening PURCHASE without a package row when its second write fails; the create result and package detail display its ID for reconciliation.

Credit usage, billing preview, and renewal status reads bypass the browser response cache so staff see the current ledger after a write or a partial write. All actions are initiated by staff. There is no scheduled renewal, expiration, usage, billing, or ledger adjustment.
