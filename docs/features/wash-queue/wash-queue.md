# WashQueue

WashQueue is a shared washer and tumble-dryer basket queue for signed-in staff. Washers and dryers use the same booking form, statuses, actions and permissions. A sender photographs a basket and may add a free-text instruction or washing programme. It is independent of orders and JobTickets. Each `machine_id` has its own FIFO queue, ordered by createdAt ascending; the frontend groups baskets and enforces FIFO, while the server only stores the selected machine id. Only the first Pending basket of each machine has the Load action, and only operators get it; later Pending baskets of that machine cannot be loaded through the UI until they reach the front.

Every basket is weighed on the scale twice, and each weighing needs a photo of the basket on the scale as evidence. The sender enters the dry basket weight (`weightBeforeKg`) when booking; the operator enters the washed (wet) weight (`weightAfterKg`) when unloading. A booking starts Pending (Waiting). Loading changes Pending to In Progress (In machine), unloading changes In Progress to Completed (Ready for pickup), and collection changes Completed to Collected. Cancellation changes Pending, In Progress or Completed to Cancelled; earlier action stamps are kept. Each action stamps its corresponding timestamp and StaffId, plus updatedAt and updatedBy. Created and updated audit timestamps are produced by the existing repository audit configuration; action timestamps use formatBangkokTimestamp. All business timestamps use yyyy-MM-dd HH:mm:ss in Asia/Bangkok.

GET /api/wash-queue returns every Pending, In Progress and Completed basket, plus Collected and Cancelled baskets updated today in Bangkok. The result is an unpaginated array sorted by createdAt ascending in the standard success envelope. GET /api/machines requires the same approved-staff authentication and returns only ACTIVE Machines in an unpaginated standard success envelope, sorted by type (WSH before DRY), sortOrder ascending (null last), then id. Other methods return 405. POST /api/wash-queue accepts machineId (required trimmed non-empty string), photoUrl (a non-empty string, the booking photo taken on the scale), weightBeforeKg (required number) and optional instruction (string or null), and returns the created basket with HTTP 201. The server generates WQ- followed by generateShortId(), sets Pending and workMinutes null, and takes both audit actors from authenticated req.staff.staffId. Before writing, the server validates machineId against an ACTIVE row in Machines and stores it as machine_id; unknown, MAINTENANCE or RETIRED machines return 422 with no write. Client-supplied identity, status and audit fields are rejected.

PATCH /api/wash-queue/:id accepts an `action`: load, collect or cancel alone, or unload together with `weightAfterKg` (number) and `unloadPhotoUrl` (the photo taken on the scale). It returns the updated basket. PATCH rejects machineId; the booked machine cannot be changed. An unknown id returns 404; an action incompatible with the current status returns 409 and an explanatory message. The frontend displays that message and reloads the list. Reads normalize native Sheets/GViz datetime values to the canonical Bangkok format, and blank nullable write echoes to null.

Cancellation, loading, unloading and collection are gated in the frontend only (see the permission table); the server has no role, ownership or FIFO checks, by owner decision. An operator is an admin or staff whose Position, trimmed and compared case-insensitively, equals WashOperator; Position comes from the existing /api/staff/me service and sender names from the staff store. Cancellation asks for confirmation. Shared Sheets reads and writes do not provide atomic compare-and-set across operators, so the status check is a read-before-update check, not a transactional concurrency guarantee.

Rows also carry `weightBeforeKg`, `weightAfterKg`, `unloadPhotoUrl` and `machineId`, each nullable on reads for legacy rows; new bookings require `machineId`.

The page is one screen at `/wash-queue`, so every staff member sees the whole queue of the current mode. It uses `ListPageLayout` with `GenericTabs` as the filters strip: All, Waiting, In machine and Ready, each with a count. The active tab lives in the `?tab=` query (`waiting`, `in-machine` or `ready`; All has no key) and changes with `router.replace`. A floating switch at the bottom of the screen chooses Washer or Dryer; the mode lives in the `?mode=` query (`dryer`; Washer has no key) and changes with `router.replace`, keeping the other query keys. A basket belongs to Dryer when its `machineId` starts with `DRY`; every other basket, including legacy rows with no machine, belongs to Washer. Tabs, counts, sections, empty states and the swipe hint reflect only the current mode. The switch (`WashQueueModeSwitch`) is a 300×60 dark-primary rounded-square track with a lime rounded-square knob over the active half; each half has an icon (`local_laundry_service`, `mode_heat`) and the label Washer or Dryer, and the inactive half is faded white. It floats centred above the safe-area inset with one soft shadow, and the list ends with a spacer that clears it. The page loads the machines list into the machines store (`src/data/machines`) once on mount. All shows the sections from top to bottom as In machine, Waiting and a collapsible Ready for pickup, each hidden when empty; a filtered tab shows only its section, or one empty state when that list is empty. When the current mode's queue is empty one empty state shows. Each section header has a lime left bar, the title and a tiny uppercase subtitle; there is no basket counter (the tabs carry the counts). The Photo button sits at the right end of the header row of the topmost visible section; `WashQueueSection` exposes it as the `action` slot, beside the Ready section's collapse button rather than inside it. A hint line under the tabs ("Left: cancel", "Right: load / unload / pick up", limited to what the visible rows allow) is shown only when the user has at least one swipeable row. Rows are white cards with a weight column (the dry weight, or the washed weight on Ready rows, with "kg" under it), a thin divider, the sender with a "You" badge on the user's own baskets and a "Next" badge on the first waiting basket of each machine, an uppercase status line showing the booked machine label (e.g. DRYER 8 KG; legacy rows without a machine show IN MACHINE, WAITING or READY FOR PICKUP instead), coloured by status, a meta line (booking time as `today HH:mm` otherwise the Bangkok date and time — In machine rows show the load time instead as `Started at HH:mm:ss`, prefixed with the date when not today — then the note; Ready rows start it with "Dry X kg") and a 56 px photo tile that opens the shared photo viewer. The tile carries a status dot (dashed Waiting, primary sync In machine, lime check Ready), and Ready rows also show a small tile for the unload photo. The machine label is built in English from the Machines list as the type word and capacity, for example DRYER 15 KG or WASHER 10 KG (the Machines `name` column is not displayed), and falls back to the raw machine id when the machine is not in the list or has no capacity. FIFO is per machine: the Next badge and the Load action count the waiting baskets of the same `machineId` within the current mode, and legacy rows with no machine form one group. Booking is the Photo button (the shared `StickerFab` at 48 px, in the header row of the topmost visible section, or above the empty state when the current view has no section): the shared `WeightPrompt` ("Weigh the basket", explaining the photo must show the basket on the scale), then the shared CameraOverlay, then upload via uploadToStorage(file, 'wash-queue'), then a "Book this basket?" confirmation with the photo preview, the weight (e.g. "12.5 kg") with a Re-weigh button that discards the photo and starts over, a required machine picker, and an optional note (`FormTextarea`, `value`/`input` bindings so Thai IME composition works) with Book and Discard. The picker (`WashQueueMachinePicker`) is three equal rounded-square tiles for the ACTIVE machines of the current mode, each with the capacity large and the type word Washer or Dryer small; unselected tiles are white with an outline border and the selected tile is dark primary with white text. A "Required" hint shows while nothing is chosen, nothing is pre-selected, Book stays disabled until a machine is chosen, the choice resets when the draft is discarded or booked, and it is sent as `machineId`. Success shows a transient notice for five seconds, centred just above the mode switch; failures show a tinted error notice (inside the confirmation for booking, at the top of the list otherwise). Actions are swipe gestures on `BaseSwipeCard` rows, shown only where the permission table allows them. Swiping right reveals a lime panel with the primary action: Load (the first waiting basket of each machine, operators), Unload (an In machine basket, operators) or Pick up (a Ready basket, its sender or an operator). Swiping left reveals a red Cancel panel on a basket the user may cancel (see the permission table), which opens the confirmation; for an In machine or Ready basket the confirmation says the basket is already in a machine or ready for pickup. Rows with no allowed action are not swipeable, and a swipe in an unavailable direction snaps back. Only one row stays swiped open: opening another row, or pressing anywhere outside the open row (a page-level capture `pointerdown` listener), snaps it back, while a press on the open row's own action panel still runs the action. In machine rows have a running timer: the whole card wears the Weight field frame from `WeightPrompt` (2px primary border, radius 11px 15px 12px 14px, 4px 4px hard shadow in primary darkened 30%), set on the list item so the swipe panels stay clipped inside it and the frame, shadow and tab are never cut off, and a dark primary tab on the top-left edge (the same tab tokens as the field's "Weight" label, including the -3° tilt, drawn above the card and any open swipe panel) shows a clock icon and the elapsed time since `loadedAt` as H:MM:SS with tabular digits (`role="timer"`, not focusable). `loadedAt` is a Bangkok `yyyy-MM-dd HH:mm:ss` string parsed as Asia/Bangkok through `sheetTimestampMs`; when it is null or unparsable the row keeps the frame without a tab. Once the elapsed time passes `RUNNING_LONG_SECONDS` (1:30:00, in `format-elapsed.ts`) the tab, frame and shadow switch to the warning colour, as the field's invalid state switches to red. One page-level ticker (`useNow`, one interval, paused while the document is hidden) drives every timer, and the In machine list uses a 24px gap so a tab clears the previous card's shadow. Each swipeable row also carries visually hidden buttons for the same actions that Tab reaches and that appear while focused, because `BaseSwipeCard` has no keyboard path for its swipe panels. A row with a write in flight is disabled and shows an "Unloading…", "Picking up…" or "Updating…" veil with a spinner. Unload (operators only) runs the same weight prompt ("Weigh the washed basket") and camera, then uploads the photo with uploadWashQueuePhoto and sends one PATCH with the weight and photo URL; closing the prompt or camera saves nothing, and the row shows its own busy state during upload and save. Every row shows its before weight; Ready for pickup rows show "before → after kg". The photo viewer lists the booking photo and, for baskets that have one, the unload photo right after it. Each row has its own saving state; a 409 shows the server message and reloads the list. The weigh flow and the photo viewer are route-owned query overlays (`?weigh=book` or `?weigh=unload:<id>` opens the prompt, adding `&weight=<kg>` opens the camera; `?photo=<id>`) that close with Back. The page refreshes every 30 seconds while mounted (skipped while a write is in flight) and when the document becomes visible again, and disposes its timer on unmount. It is excluded from KeepAlive so booking state does not survive navigation away.

| Action | Who sees it |
|---|---|
| Book (Photo button) | Everyone |
| Cancel a Pending basket | The sender (`createdBy` equals the current StaffId), or an operator |
| Cancel an In Progress or Completed basket (stuck machine, test rows) | Admins only |
| Load (first Pending) and Unload | Operators only |
| Pick up (Completed) | The sender, or an operator |

Other people's baskets are view-only for non-operators.

Persistence uses the existing WashQueue tab, columns A through U (21 fields), in JOB_TICKETS_SPREADSHEET_ID. Capabilities are append and update; rows are never deleted. work_minutes is a nullable number reserved for future KPI use and is always written null on create; actions never change it. There is no duration calculation in this feature. The read-only Machines tab shares JOB_TICKETS_SPREADSHEET_ID, uses columns A through I, disables append/update/delete and has no audit stamping.
